# 시장아파트 답사 아카이브

시장과 주거가 하나의 건축물로 결합된 **시장아파트**를 전국 단위로 답사·기록하고, 입지와 형태를 비교 분석하기 위한 연구 도구입니다. 건축학과 논문 연구를 위해 만들어졌습니다.

사진 저장 앱이 아니라 **공간 데이터 아카이브**를 목표로 합니다. 모든 프로젝트는 세 층의 데이터를 함께 갖습니다.

| | |
|---|---|
| **공간 데이터** | 어디에 있는가 — 좌표, 행정구역, 철도역·터미널·시장과의 거리 |
| **건축 데이터** | 어떤 건물인가 — 층 구성(지하·시장·주거·지상 전체), 시장–주거 결합 방식, 규모, 현재 상태 |
| **관찰 데이터** | 현장에서 무엇을 발견했는가 — 사진, 답사 기록, 연구 메모 |

---

## 빠르게 시작하기

```bash
git clone <이 저장소 주소>
cd market-apartment-archive
npm run dev          # http://localhost:5173
```

설치할 의존성이 없습니다. Node 18 이상이면 바로 돌아갑니다. `src/` 의 파일을 저장하면 다시 빌드되고, 브라우저를 새로고침하면 반영됩니다.

```bash
npm run build        # dist/index.html · dist/preview.html 생성
npm run check        # 문법 검사
npm run geo          # 행정경계 데이터 재생성 (평소에는 실행할 일 없음)
```

### 왜 번들러가 없는가

Artifact 로 게시하면 외부 스크립트를 불러올 수 없어 결과물이 어차피 한 파일이어야 합니다. 순서대로 이어 붙이면 끝나는 일이라 도구를 늘리지 않았습니다. 모듈이 아니라 **전역 스코프를 공유**하므로, `scripts/build.mjs` 의 `SCRIPTS` 배열 순서가 곧 의존 순서입니다.

---

## 배포

`dist/index.html` 을 Artifact 에 게시합니다. 규칙이 하나 있습니다.

> **항상 같은 Artifact 를 갱신할 것.** 새 Artifact 로 게시하면 새 빈 저장소가 만들어지고, 그동안 쌓은 답사 기록에 접근할 수 없게 됩니다.

Claude 대화에서 기존 아티팩트 URL을 알려주고 `dist/index.html` 을 게시하면 같은 링크가 갱신됩니다. 자세한 이유는 [docs/DATA_POLICY.md](docs/DATA_POLICY.md).

로컬(`npm run dev`)에서는 계정 저장소를 쓸 수 없으므로 IndexedDB 로 자동 대체됩니다. 즉 **개발용 데이터와 실제 답사 데이터는 서로 섞이지 않습니다.**

## 기능

**지도** · 외부 타일 없이 동작하는 전국 지도. 팬·핀치줌, 시군구 경계 자동 노출, 축척바. 좌표를 찍으면 시·도와 시·군·구를 자동 판별합니다. 시장아파트 / 현재역 / 과거역(1970–80s) / 철도 노선 / 터미널 / 시장 레이어를 각각 켜고 끄고, 반경 500m·1km·2km 를 겹쳐 봅니다.
참조 지점은 위도·경도를 직접 넣거나, 지도에서 찍거나, 다른 지도에서 복사한 문자열(십진수 · 도분초 · 지도 링크)을 붙여넣어 지정합니다. 넣는 즉시 어느 시·군·구에 떨어지는지 보여주므로 위경도를 바꿔 넣는 실수를 바로 알아챕니다.
마커를 누르면 그 시장아파트의 상세 화면으로 곧장 들어갑니다(역·터미널·노선은 정보창이 열립니다). 마커에 커서를 올리면 이름·지역·층수(참조 지점은 종류·연도, 노선은 길이)가 쪽지로 뜹니다. 전국 축척에서는 이름을 다 그리면 겹쳐 읽히지 않기 때문에 커서를 따라다니는 방식으로 보여줍니다.
철도 노선은 지도를 눌러 직접 그립니다. 현재 노선과 과거 노선을 따로 그려 레이어로 비교하고, 각 프로젝트에서 **노선까지의 최단거리**가 자동으로 계산됩니다.

**프로젝트** · 기본 24개 항목과 사용자가 직접 만드는 항목(7가지 형식). 엑셀형 표에서 정렬·검색·다중 선택. 필터는 시·도/시·군·구·결합유형·상태·주차장·태그에 더해 상세 필터로 건축연도·답사일 범위, 층수, **역·터미널 근접(500m·1km·2km·그 밖)**, 지하층 유무, 사진 유무, 사용자가 만든 선택형 항목까지 씁니다.
층은 **지하 층수 · 시장 층수 · 아파트 층수 · 지상 전체 층수**를 따로 적습니다. 지하는 주차·하역·창고처럼 성격이 달라 지상 층수와 합산하지 않고 «지하 2층 · 시장 2 + 주거 5층 · 지상 전체 7층» 으로 표기합니다.

**답사 기록** · 사진 다중 업로드 — 몇 장째인지 진행 표시를 보여주고, 한 장이 실패해도 나머지는 계속 올립니다. **한 장도 조용히 빠뜨리지 않습니다**: 저장이 몰려 거절되면 잠깐 쉬었다 다시 시도하고, 그래도 안 되면 무엇이 왜 실패했는지 표로 보여주고 그 자리에서 다시 시도할 수 있습니다. 자동 압축(문서 한도에 맞춰 크기를 단계적으로 줄임)·썸네일·선명도 측정, 카테고리·촬영일·입면 방향·태그. 분류별 연구 노트.
갤러리에서 「선택」을 켜면 여러 장을 골라 **한 번에** 카테고리·입면 방향·촬영일을 바꾸고 태그를 더하거나 삭제할 수 있습니다. Shift 를 누른 채 누르면 그 사이가 통째로 선택되어, 연속으로 찍은 구간을 한 번에 분류합니다.

**입면** · 같은 면 사진을 방향별로 묶고 선명도순으로 추천 → 네 모서리 지정 → 호모그래피로 원근 보정 → 기울기·대비·흑백·선 추출.
추출한 선은 다시 다듬습니다. 선 단순화 · 짧은 선 제거 · 건물 외곽선 · 층 경계선 · 창호 구분 · 간판 영역 정리 · 수직/수평선만 — 버튼으로 고르거나 "간판은 지우고 층 경계선만 남겨줘" 처럼 문장으로 지시할 수 있습니다(AI가 문장을 연산으로 옮기고, 쓸 수 없을 때는 낱말로 해석합니다). 원본 추출 결과는 그대로 두고 매번 다시 계산하므로 언제든 되돌아갑니다.
내보내기는 PNG · JPG · PDF(보정 이미지 + 선을 벡터로) · SVG · DXF(R12).
사진을 도면으로 자동 변환하지 않습니다. **트레이싱 베이스 이미지**를 만드는 것이 목적입니다.

**공공데이터 가져오기** · QGIS 에 레이어를 얹듯 **CSV · GeoJSON · Shapefile(.shp+.dbf)** 과 이들을 담은 **ZIP** 을 그대로 올립니다. 공공데이터포털의 EUC-KR(CP949) 파일도 자동으로 읽고, 이름·위도·경도·연도 열을 짐작해 미리 골라 둡니다.
좌표계는 `.prj` 에서 읽거나 좌표값의 크기로 짐작합니다 — WGS84 경위도, UTM-K(5179), 중부·서부·동부·동해원점 TM(GRS80 및 구 Bessel 좌표계), Web Mercator. 구 좌표계는 Molodensky-Badekas 데이텀 변환까지 적용합니다(pyproj 대조 오차 1cm 미만).
가져오기 전에 표와 지도로 미리 보고, 남한 범위 밖 좌표는 걸러 냅니다. 들여온 항목에는 출처가 남아 **한 파일씩 되돌릴 수** 있습니다.

**분석** · 지역 분포(대도시 / 그 외 구분), 결합 유형, 건축 연대, 교통시설 거리 중앙값과 반경별 집계, 현재역−과거역 거리 차, 규칙 기반 유형 가설, 기록된 데이터만 근거로 답하는 AI 질의.

**출력** · **.pptx 발표자료**(파워포인트·키노트·구글 슬라이드에서 그대로 편집됩니다). 표지 · 연구 개요 · 전국 분포 지도 · 사례 위치 · 기본 정보 · 사진 · 입면 · 답사 기록 · 건축적/도시적 특징 · 교통시설 · 비교 · 분석 메모 · 결론 중 넣을 슬라이드를 직접 고릅니다. 지도는 앱이 직접 그려 이미지로 넣습니다.
답사 보고서와 PDF 슬라이드(인쇄 → PDF), CSV, 사진 원본까지 포함한 JSON 백업도 그대로 있습니다.

## 자주 하는 작업

**항목 추가** — 앱 안에서: 설정 → 사용자 정의 항목. 코드 수정 불필요.
**기본 항목 추가** — `src/core.js` 의 `BASE_FIELDS` 에 `{k, label, type}` 추가. 표에도 넣으려면 `src/projects.js` 의 `TABLE_COLS` 에 키를 추가합니다. 기존 프로젝트에는 빈 값으로 나타나며 데이터는 그대로입니다.
**저장 구조 변경** — `SCHEMA_VERSION` 을 올리고 `MIGRATIONS` 에 항목을 추가합니다. 규칙은 [docs/DATA_POLICY.md](docs/DATA_POLICY.md).
**참조 지점(역·터미널) 일괄 입력** — 지도 화면의 「공공데이터 가져오기」 또는 설정 → 가져온 데이터. 공공데이터포털에서 받은 CSV·SHP·ZIP 을 그대로 올리면 됩니다.
**좌표계 추가** — `src/import.js` 의 `CRS_LIST` 에 `{id, label, kind:'tm', ell, lat0, lon0, k0, x0, y0}` 를 넣으면 끝입니다. `.prj` 이 있는 파일은 목록에 없어도 파라미터를 직접 읽어 변환합니다.
**철도 노선 입력** — 지도 화면의 「현재/과거 노선 그리기」로 점을 찍고 완료하면 됩니다. 과거 노선은 출처를 메모에 남겨두면 그대로 논문 각주가 됩니다.
**PPT 슬라이드 종류 추가** — `src/pptx.js` 의 `DECK_SECTIONS` 에 항목을 넣고 `composeDeck` 에 그리는 코드를 씁니다. 도형은 `tx`·`rect`·`pic`·`table` 네 가지면 충분합니다.

## 얼마나 담을 수 있나

아티팩트 한 개의 데이터베이스는 문서를 **5,000개**까지, 문서 하나는 **256 KiB**까지 담습니다(런타임 계약값).

사진 1장은 문서 2개(메타+썸네일, 원본)를 써서 **약 2,500장**까지 담깁니다.

> v1.8.0 에서 썸네일·메타를 프로젝트 단위로 묶어 4,400장까지 늘렸다가 **되돌렸습니다.** 묶음에 한 장을 더하려면 공유 문서를 읽고 고쳐 되써야 하는데, 이 저장소는 last-writer-wins 이고 방금 쓴 것이 곧바로 읽힌다는 보장이 없어 연달아 올린 사진의 메타가 서로를 지웠습니다. 원본은 무사했지만 목록이 사라졌습니다. 자세한 경위는 [docs/DATA_POLICY.md](docs/DATA_POLICY.md) 의 v2.0.0 항목에 남겼습니다.

**백업 파일 하나에 아카이브 전체가 들어갑니다** — 프로젝트·사진 원본·답사 기록·참조 지점·사용자 정의 항목까지. 설정 → 복원에 그 파일을 넣으면 그대로 돌아옵니다. 사진 120장 규모로 «백업 → 저장소 전부 삭제 → 복원» 을 돌려 **원본이 바이트까지 같게 되살아나는 것**을 확인했습니다(11.9MB, 복원 0.6초). 백업할 때 무엇이 들어갔는지 화면에 보여줍니다.

사진이 사라지지 않도록 세 겹을 두었습니다. 업로드가 끝나면 **저장소를 다시 읽어** 실제로 들어갔는지 확인하고, 프로젝트의 사진 수가 **가장 많았을 때보다 줄면** 상세 화면이 경고하며(줄어든 수로 조용히 덮어쓰지 않습니다), 백업이 오래되면 설정이 알려 줍니다.

**설정 → 정리 → 사라진 사진 되살리기**는 원본은 있는데 목록에서 사라진 사진을 찾아 되살립니다. 갤러리의 「선택 → 프로젝트 옮기기」로 원래 프로젝트에 나눠 줄 수 있습니다.

**설정 → 정리 → 저장소 청소**는 쓰이지 않는 문서(주인 없는 원본, 사라진 프로젝트의 자료, 옛 스냅샷, 휴지통)를 찾아 되찾을 용량을 보여주고 **고른 것만** 지웁니다. 업로드가 중간에 끊겼을 때 남는 «주인 없는 원본»이 가장 크게 낭비되는 항목입니다.

남은 장수와 장당 문서 수는 **설정 → 저장 공간**에 실제로 재서 나옵니다. 예전 방식으로 저장된 사진이 있으면 거기서 「묶어 담기」로 옮길 수 있고, 옮긴 결과를 확인한 뒤에만 옛 문서를 지웁니다.
한도가 차도 기존 기록은 계속 수정할 수 있고, 새로 만드는 것만 막힙니다.
