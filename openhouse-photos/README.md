# 오픈하우스 사진함

오픈하우스서울 투어 참가자가 찍은 사진을 건축물별로 모아, 건축가(소장님)께 전달하는 공유 폴더 웹사이트입니다.

## 누가 무엇을 할 수 있나

| | 사진 보기 | 사진 올리기 | 사진 삭제 | 건축물 관리 |
|---|---|---|---|---|
| **참가자** (이름+비밀번호 가입) | 모든 건축물 | ○ | **본인 사진만** | ✕ |
| **소장님** (로그인 없음, 전용 링크) | **링크 받은 건축물만** | ✕ | ✕ | ✕ |
| **관리자** | 모든 건축물 | ✕ | 모든 사진 | 추가·수정·삭제, 링크 발급 |

- 소장님 링크는 `https://주소/s/긴무작위문자열` 형태입니다. 관리자 화면의 **소장님 링크 복사**로 복사해 문자·메일로 보내면 됩니다.
- 링크가 엉뚱한 곳에 전달됐다면 **링크 재발급**을 누르세요. 이전 링크는 즉시 막힙니다.
- 사진마다 촬영자 이름(`© 이름`)이 붙고, ZIP 다운로드 파일명에도 들어갑니다.
- 참가자가 비밀번호를 잊으면 관리자 → **참가자** 메뉴에서 새로 정해줄 수 있습니다.

## 실행

Node.js **22.13 이상**만 있으면 됩니다. 설치할 패키지가 없습니다.

```bash
cd openhouse-photos
ADMIN_PASSWORD=관리자비밀번호 JOIN_CODE=OHS2026 npm start
```

http://localhost:3000 에서 열립니다.

| 환경변수 | 설명 | 기본값 |
|---|---|---|
| `ADMIN_PASSWORD` | 관리자 비밀번호 (**필수**) | — |
| `JOIN_CODE` | 참가자 가입 코드. 현장에서 알려주면 아무나 가입하는 걸 막을 수 있음. 비우면 누구나 가입 | 없음 |
| `PORT` | 포트 | `3000` |
| `DATA_DIR` | DB와 사진이 저장될 폴더 | `./data` |
| `MAX_UPLOAD_MB` | 사진 1장 최대 크기 | `40` |
| `COOKIE_SECURE` | HTTPS 프록시 뒤에서 `1` (보통 `X-Forwarded-Proto`로 자동 감지) | — |

```bash
npm test     # 권한 규칙 자동 검사 (남의 사진 삭제 불가, 링크별 접근 제한 등)
npm run dev  # 개발용 (관리자 비밀번호 admin1234, 파일 저장 시 재시작)
```

## 배포 (Railway)

사진이 서버 디스크에 저장되므로 **볼륨(저장 공간)을 꼭 붙여야** 합니다. 붙이지 않으면 재배포 때 사진이 모두 사라지고, 관리자 화면에 빨간 경고가 뜹니다.

1. **가입** — [railway.com](https://railway.com) 에서 GitHub 계정으로 로그인. 실제 운영하려면 Hobby 요금제가 필요합니다(요금은 Railway 요금 페이지 확인).
2. **프로젝트 만들기** — `New Project` → `Deploy from GitHub repo` → 이 저장소 선택.
   (처음이면 Railway에 저장소 접근 권한을 주라는 화면이 나옵니다.)
3. **폴더·브랜치 지정** — 만들어진 서비스를 클릭 → `Settings`
   - `Root Directory` : `/openhouse-photos`
   - `Branch` : 이 앱이 들어 있는 브랜치 (main에 합쳤다면 `main`)
   - 그러면 `Dockerfile` 을 찾아 자동으로 빌드합니다.
4. **환경변수** — `Variables` 탭에서 추가
   - `ADMIN_PASSWORD` = 관리자 비밀번호 (길고 어렵게)
   - `JOIN_CODE` = 현장에서 참가자에게 알려줄 코드 (선택)
5. **볼륨 붙이기** — 프로젝트 화면 빈 곳을 우클릭(또는 `⌘K`) → `Volume` → 이 서비스에 연결, Mount path `/data`.
   경로는 앱이 자동으로 알아냅니다.
6. **주소 만들기** — `Settings` → `Networking` → `Generate Domain`. `https://○○○.up.railway.app` 주소가 생깁니다. HTTPS는 자동.
7. **확인** — 주소로 들어가 관리자 로그인 → 빨간 경고가 없으면 끝. 건축물을 추가하고 휴대폰으로 사진 한 장 올려보세요.

이후 브랜치에 코드를 푸시하면 자동으로 다시 배포되고, 사진은 볼륨에 그대로 남습니다.

**백업** — 볼륨 안의 `app.db` 와 `uploads/` 가 전부입니다. 행사가 끝나면 관리자 화면에서 건축물별 `전체 다운로드` 로 ZIP을 받아두는 것이 가장 간단합니다.

**다른 곳에 올릴 때** — `Dockerfile` 이 있으므로 Fly.io, Render, 개인 서버 어디서든 돌아갑니다. 저장 공간을 붙이고 `DATA_DIR` 을 그 경로로, `ADMIN_PASSWORD` 를 지정하면 됩니다. 반드시 HTTPS로 서비스하세요.

## 구조

```
Dockerfile       배포용 이미지
server.js        API · 권한 검사 · 업로드 · 파일 제공 (Node 내장 SQLite 사용)
lib/zip.js       전체 다운로드용 ZIP 스트리밍 (4GB 넘으면 ZIP64)
public/
  index.html, app.js   참가자·관리자 화면
  share.html, share.js 소장님 화면
  common.js, style.css 공용
test/            권한 시나리오 테스트
```

- 권한 검사는 전부 서버에서 합니다. 화면에서 버튼을 숨기는 것은 편의일 뿐입니다.
- 업로드 파일은 내용(매직 바이트)으로 JPG·PNG·WEBP·HEIC만 받습니다.
- 썸네일은 업로드할 때 브라우저가 만들어 함께 보냅니다. 서버에 이미지 라이브러리가 필요 없습니다. (크롬에서 HEIC를 올리면 썸네일 없이 원본만 저장되고, 목록에는 파일명이 대신 보입니다. 아이폰 사파리는 보통 JPG로 바꿔 올립니다.)
