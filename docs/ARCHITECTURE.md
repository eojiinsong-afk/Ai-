# 구조

## 저장소 계층

앱은 저장소를 직접 부르지 않고 `S.store` 라는 얇은 인터페이스만 씁니다.

```js
S.store.list(coll, [field, '==', value])   // 목록
S.store.get(coll, id)                      // 한 건
S.store.put(coll, id, data)                // 통째로 쓰기
S.store.del(coll, id)                      // 삭제
```

두 가지 구현이 있고 부팅할 때 자동으로 골라집니다.

| 백엔드 | 언제 | 특징 |
|---|---|---|
| `makeDbBackend` | Artifact 로 게시됐고 `db` capability 가 허용될 때 | 계정 저장소, 기기 간 동기화 |
| `IDB` | 그 밖의 모든 경우 (로컬 개발 포함) | IndexedDB, 이 브라우저에만 |

새 백엔드(예: Supabase)를 붙이려면 위 네 함수를 구현하고 `boot()` 에서 선택하게 하면 됩니다. 나머지 코드는 고칠 것이 없습니다.

썸네일을 원본과 떼어 둔 이유: 목록·갤러리·비교·보고서는 모두 썸네일만 필요하고, 원본을 따로 두면 사진 20장짜리 프로젝트를 여는 비용이 4MB에서 300KB로 떨어집니다.

### 왜 묶어 담는가

문서 하나는 256 KiB, 아티팩트 하나는 문서 5,000개가 한도입니다. 원본(150–220KB)은 어차피 문서 하나를 채우지만
썸네일(15–25KB)과 메타(약 300B)는 한 장씩 저장하면 문서 하나를 거의 비운 채 씁니다.
프로젝트 단위로 묶으면 사진 1장당 문서가 **2개 → 약 1.13개**가 되어 담을 수 있는 장수가 **약 2,500장 → 약 4,400장**으로 늘어납니다.
곁들여 얻는 이점이 하나 더 있습니다 — 한 프로젝트의 사진 20장을 일괄 수정할 때 쓰기가 20번에서 **1번**으로 줄어듭니다.

- 한도는 글자 수가 아니라 **직렬화한 바이트**로 잽니다(`jsonBytes`). 한글 메모는 글자당 3바이트라 글자 수로 재면 어긋납니다.
- 메모가 길어져 묶음이 한도를 넘으면 그 사진만 다른 묶음으로 옮깁니다(`PhotoStore.update` 의 overflow 처리).
- 앱은 `PhotoStore` 하나만 부릅니다(`list`/`listAll`/`get`/`add`/`update`/`remove`). 묶음과 옛 문서가 섞여 있어도 화면은 구분하지 않습니다.
- 백업 파일 형식은 **평평한 사진 배열 그대로**입니다. 내부 배치가 바뀌어도 예전 백업이 그대로 복원됩니다.

## 지도 엔진 (`src/map.js`)

외부 지도 라이브러리를 쓰지 않습니다. 필요한 것이 (1) 오프라인 동작 (2) 시군구 단위 판별 (3) 임의 레이어뿐이라, 직접 그리는 편이 가볍습니다.

- **투영**: 등거리 원통. `x = 경도 × cos(36°)`, `y = −위도`. 남한 범위에서 왜곡이 무시할 만합니다.
- **경계**: SVG `<path>` 를 그룹 하나에 넣고 `translate/scale` 로 팬·줌. 축척이 4200을 넘으면 시군구 경계와 라벨이 나타납니다.
- **마커**: 매 변환마다 화면 좌표로 다시 계산합니다(수백 개 규모에서 충분히 빠름).
- **좌표 → 행정구역**: 시군구 폴리곤에 대한 점-다각형 판정(`MAP.reverse`). 경계선 근처에서는 어긋날 수 있어 사용자가 고칠 수 있게 해 둡니다.
- **거리**: 점끼리는 `haversine`, 점–노선은 `pointToPathDist`(국지 평면 근사 + 선분 투영). `nearestFacilities` 가 종류별 최근접 하나씩을 돌려주며, 노선(`rail`/`oldrail`)도 같은 표에 함께 들어갑니다.
- **노선 그리기**: `MAP.startLine(kind)` → 지도 클릭이 `MAP.draft` 에 점을 쌓음 → 「완료」가 `lineForm()` 을 열어 이름·연도·출처를 받아 저장. 편집은 같은 문서에 `path` 만 다시 씁니다.
- **마커 클릭**: 팬을 위해 `setPointerCapture` 를 쓰기 때문에 브라우저에 따라 `click` 이 마커가 아니라 `#mapsvg` 로 갑니다. 그래서 마커마다 `onclick` 을 붙이지 않고, 탭으로 판정된 `pointerup` 에서 `document.elementFromPoint` 로 직접 히트테스트합니다(둘레 4곳도 함께 봐 손가락 오차를 흡수). 시장아파트는 상세 화면으로, 참조 지점은 정보창으로 갑니다.
- **마커 쪽지**: `bindTip()` 이 `#mapsvg` 에 델리게이트로 한 번만 붙습니다. `drawMarkers` 가 매 변환마다 `#gMk` 의 내용을 갈아치우지만 `#gMk` 자체는 남으므로 다시 붙일 필요가 없습니다. 문구는 마커를 그릴 때 `data-tip` 에 넣어 둡니다(`prjTip`/`facTip`). 마우스일 때만 뜨고, 드래그 중에는 감춥니다.
- **정적 지도**: `staticMapSvg()` 가 CSS 변수 대신 리터럴 색(`MAPPAL`)으로 독립 SVG 를 만들고, `svgToJpeg()` 가 캔버스로 굽습니다. 외부 참조가 없는 SVG 라 캔버스가 오염되지 않아 `toDataURL` 이 됩니다. 보고서·PDF 슬라이드·PPTX 가 모두 이 하나를 씁니다.

## 입면 보정 (`src/elevation.js`)

1. 네 모서리(사진 기준 비율 좌표) → 출력 사각형으로 가는 **호모그래피**를 8×8 선형계로 풉니다(`homography`, `solve8`).
2. 출력 픽셀마다 역변환해 원본을 **양선형 보간**으로 샘플링합니다.
3. 후처리: 대비 → 흑백 → Sobel 엣지 → 임계값.
4. 선 추출은 이진 엣지에서 가로/세로 방향의 긴 런(run)을 찾아 선분으로 만듭니다. 보정 후에는 주요 선이 축에 정렬되므로 이 단순한 방법이 잘 맞습니다. 결과는 `EL.raw` 에 그대로 보관합니다.
5. 선 편집(`LINE_OPS`)은 **항상 `EL.raw` 부터 다시 계산**합니다(`applyLineOps`). 그래서 어떤 조합을 눌러도 원래대로 돌아갈 수 있고, 연산끼리 순서를 바꿔도 상태가 오염되지 않습니다. 연산은 모두 `[x0,y0,x1,y1]` 배열 하나를 받아 배열 하나를 돌려주는 순수 함수입니다.
6. 문장 지시는 `runElevCommand()` 가 처리합니다. `S.sample` 이 있으면 연산 키 목록을 JSON 으로만 답하게 하고, 없거나 실패하면 `CMD_WORDS` 의 낱말 규칙으로 고릅니다. 어느 쪽이든 실제 계산은 위의 순수 함수들이 합니다 — AI 가 이미지를 고치는 것이 아닙니다.
7. DXF 는 R12(AC1009) 형식의 `LINE` 엔티티로 씁니다. 1픽셀 = 1도면단위, 원점은 좌하단. PDF 는 `buildPdf()` 가 직접 씁니다 — JPEG 를 `DCTDecode` 로 넣고 그 위에 선을 벡터 경로로 얹습니다(xref 오프셋을 바이트 단위로 계산).

한계를 분명히 해 둡니다. 이것은 **자동 도면화가 아니라 트레이싱 베이스 제작**입니다. 결과 이미지는 카메라 렌즈 왜곡(배럴)을 보정하지 않고, 건물이 실제로 직육면체가 아니면 오차가 남습니다.

## AI 질의 (`src/analysis.js`)

Artifact 의 `sample` capability 로 Claude 에게 묻습니다. 프롬프트에 넣는 것은 **기록된 데이터에서 생성한 표**뿐이며, 다음을 강제합니다.

- 데이터에 없는 사실을 단정하지 않을 것
- 결론은 가설로 제시할 것
- 어떤 프로젝트를 근거로 삼았는지 밝힐 것
- 표본이 적으면 한계를 먼저 말할 것

로컬 개발 환경에서는 이 기능이 꺼지고 안내 문구가 대신 보입니다.

## 사진 저장의 실패 처리 (`src/projects.js`, `src/core.js`)

사진 한 장은 문서 두 개(메타 + 원본)를 씁니다. 48장이면 96번을 몰아서 쓰게 되고, 그 과정에서 실패는 실제로 일어납니다.
답사 사진은 다시 찍을 수 없으므로 **조용히 빠지는 일이 없어야** 합니다.

- `putRetry()` — 일시적 거절(rate limit·timeout·5xx·conflict)은 지수 백오프로 최대 4번까지 다시 씁니다.
  `"rate limit exceeded"` 처럼 재시도 대상과 치명 오류의 낱말이 겹치므로 **재시도 판정을 먼저** 봅니다.
  처음 보는 오류도 일단 재시도합니다 — 한 번 더 해 보는 값이 사진 한 장을 잃는 값보다 쌉니다.
  문서 한도 초과·저장 공간 부족·권한 오류만 즉시 포기합니다.
- `encodeWithin()` — 1500 → 1200 → 1000 → 820 → 640px 로 내려가며 문서 한도(220KB) 안에 드는 첫 결과를 씁니다.
  결과가 비정상적으로 짧으면(iOS 사파리의 캔버스 메모리 고갈로 `toDataURL` 이 빈 문자열을 돌려주는 경우) 실패로 보고 다음 크기로 넘어갑니다.
- `releaseCanvas()` — 쓰고 난 캔버스의 폭·높이를 0으로 만들어 즉시 놓아줍니다. 이것이 없으면 수십 장째부터 무너집니다.
- 원본을 쓰고 메타를 못 쓰면 원본을 지웁니다. 반쪽짜리 사진을 남기지 않습니다.
- `uploadPhotos()` 는 성공·실패를 각각 세어 **실제 숫자**를 알립니다. 실패가 있으면 원인별로 묶은 표와
  현재 문서 사용량을 보여주고, 실패한 파일만 다시 시도할 수 있게 합니다.

## 사진 다중 선택 (`src/projects.js`)

`PSEL = {on, ids, last}` 하나로 관리합니다. 선택을 누를 때마다 상세 화면 전체를 다시 그리면 스크롤이 튀므로,
`refreshGallery()` 가 카드의 클래스·체크표시·분류 딱지와 작업 막대만 바꿔 끼웁니다.
일괄 수정(`bulkPatch`)은 **문서를 통째로 되쓰는** 규칙을 그대로 지킵니다 — 이 버전이 모르는 필드도 남습니다.
태그는 덮어쓰지 않고 합칩니다. Shift 누른 채 누르면 `S.photos` 의 순서를 기준으로 두 지점 사이를 모두 고릅니다.

## 공간 데이터 가져오기 (`src/import.js`)

외부 라이브러리를 못 쓰므로 인코딩 판별·CSV·DBF·SHP·ZIP·좌표계 변환을 전부 직접 씁니다.

- **인코딩** — UTF-8 로 `fatal: true` 디코드를 시도해 실패하면 EUC-KR(CP949)로 다시 읽습니다. 공공데이터포털 CSV 가 아직 EUC-KR 인 경우가 많아 이 판별이 없으면 이름이 전부 깨집니다.
- **ZIP** — 중앙 디렉터리를 읽고, deflate 항목은 `DecompressionStream('deflate-raw')` 로 풉니다(브라우저 내장). 지원하지 않는 환경에서는 압축을 풀고 올리라고 안내합니다.
- **Shapefile** — `.shp` 는 점(1/11/21)·선(3/13/23)·면(5/15/25)을 읽고, `.dbf` 는 dBASE III 헤더를 파싱해 속성을 꺼냅니다. 문자열 인코딩은 `.cpg` 를 보고 없으면 CP949 로 가정합니다.
- **좌표계** — `.prj`(WKT)에서 이름이 아니라 **파라미터**(central_meridian, false_easting, SPHEROID …)를 읽어 투영을 구성하므로 목록에 없는 변종도 처리됩니다. `.prj` 가 없으면 좌표값의 크기로 짐작합니다(`sniffCrs`).
  변환은 Snyder 의 횡메르카토르 역변환(`tmInverse`). 구 좌표계(Korean Datum 1985, Bessel)는 **Molodensky-Badekas**(회전 기준점을 둔 10-파라미터, coordinate_frame 규약)로 옮깁니다 — 단순 7-파라미터 Helmert 로 계산하면 전국에서 20m 가량 어긋납니다.
  검증: pyproj 와 10개 좌표계 × 6개 지점을 대조해 최대 오차 7mm.
- **가져오기 규칙** — 언제나 더하기만 합니다. 같은 자리(40m 이내)의 같은 종류는 건너뛰고, 남한 범위 밖 좌표는 넣지 않습니다. 들여온 문서에 `src.batch` 를 남겨 `deleteBatch()` 로 한 파일씩 되돌립니다(새 컬렉션을 만들지 않으므로 스키마가 그대로입니다).
- **노선** — 점이 400개를 넘으면 균등 추출로 줄입니다. 문서 1건이 256KB 를 넘으면 저장되지 않기 때문입니다.

## PPTX (`src/pptx.js`)

pptx 는 OOXML 몇 조각을 담은 ZIP 입니다. 외부 라이브러리를 못 쓰므로 둘 다 직접 씁니다.

- **ZIP**: 압축 없는 store 방식(`zipStore`). CRC32 만 맞으면 규격상 완전히 유효하고, 내용의 대부분이 이미 JPEG 라 크기 손해도 거의 없습니다.
- **패키지**: `[Content_Types].xml` · `_rels/.rels` · `docProps/{core,app}.xml` · `ppt/presentation.xml`(+rels) · 슬라이드 마스터 1 · 레이아웃 1(blank) · 테마 1 · 슬라이드 N(+각 rels) · `ppt/media/*.jpeg`.
- **좌표계**: 1280×720 픽셀을 설계 단위로 쓰고 `emu()` 로 환산합니다(1px = 9525EMU, 슬라이드는 정확히 16:9). 글자도 같은 기준이라 `pt(px) = px × 75` 이면 24px 제목이 18pt 가 됩니다.
- **도형**: `tx`(텍스트 상자) · `rect` · `pic` · `table` 네 가지뿐입니다. `slideBuilder()` 가 도형 id 와 이미지 관계 id 를 자동으로 붙입니다.
- **구성**: `DECK_SECTIONS` 가 슬라이드 종류 목록이고 `scope: 'each'` 는 프로젝트마다 한 장입니다. 내용이 없는 사례별 슬라이드(사진 없음, 기록 없음)는 조용히 빠집니다. 사용자가 고른 목록은 `localStorage` 에 남습니다.
- **텍스트**: XML 이 담을 수 없는 제어문자를 `xt()` 가 걸러냅니다. 문자 하나 때문에 파일 전체가 안 열리는 사고를 막습니다.

검증은 `python-pptx` 로 열어 슬라이드 수·표·그림이 읽히는지 확인했습니다.

## 코딩 관습

- 모듈이 아닌 **전역 스코프**를 공유합니다. `scripts/build.mjs` 의 `SCRIPTS` 순서가 의존 순서입니다.
- 사용자 입력이 HTML 로 들어가는 모든 자리에 `esc()` 를 씁니다.
- 화면에 그리는 색은 CSS 변수로만 씁니다. 라이트/다크가 한 세트로 정의되어 있어 리터럴 색을 쓰면 한쪽 테마에서 깨집니다.
  예외는 **앱 밖으로 나가는 산출물**뿐입니다 — 정적 지도 SVG(`MAPPAL`), 인쇄용 `#printroot`, PPTX(`C`). 이들은 뷰어의 테마를 모르므로 인쇄용 밝은 색을 리터럴로 박습니다.
- 사용자에게 보이는 문구는 한국어. 코드 주석도 한국어로 씁니다.
